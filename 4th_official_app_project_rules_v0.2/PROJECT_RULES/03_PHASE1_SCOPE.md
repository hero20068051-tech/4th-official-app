# 03_PHASE1_SCOPE

# 【CONFIRMED】Phase 1

## ゴール
**試合前登録 → 試合開始 → 両チームの交代管理 → 自動判定 → 履歴確認・修正 → 安全な再開**
までを現場で使える状態にする。

## 必須機能

### 1. 2チーム管理
- HOME / AWAYを完全に独立管理。
- チーム名は任意。未入力時はHOME / AWAY。
- 両チームはそれぞれ独立した選手状態、出場履歴、再出場状態、後半交代機会、仮入力を持つ。

### 2. 試合前設定
- 試合時間：30分 / 35分 / その他。
- 背番号：1〜99。
- 非連番可。
- 同一チーム内の背番号重複禁止。
- 数値順で表示。
- カンマ区切り等の一括入力を許可する。
- 今回の大会ルール使用時は試合登録最大20名。
- 先発 / ベンチを設定。
- GK登録選手を1名以上に限定せず設定可能。
- GK判定用フィールド名は `isRegisteredGK` とする。
- 試合開始前は選手設定を自由に修正できる。
- キックオフ前の先発変更は試合中の「交代」として記録しない。

### 3. 開始人数
- 11名：通常開始。
- 7〜10名：警告付きで開始可能。
- 6名以下：開始不可。

### 4. 飲水設定
試合前に次のいずれかを選ぶ。
- なし
- あり・ランニング
- あり・時計停止

任意で「15分頃」等のメモを保存できる。

### 5. 試合フェーズ
- PRE_MATCH
- FIRST_HALF
- HALF_TIME
- SECOND_HALF
- FULL_TIME

操作：
- 前半開始
- 前半終了
- 後半開始
- 試合終了

前半終了・試合終了は誤操作防止確認を行う。

### 6. 時計
- インメモリのカウントだけに依存せず、実際の開始日時（timestamp）を基準に経過時間を求める。
- 画面ロック・バックグラウンド・再読込後も正しい経過時間へ復元できる設計にする。
- 通常の交代では時計を止めない。
- 飲水が「時計停止」の場合のみ、飲水開始 / 試合再開で時計を停止・再開できる。
- 前半・後半の開始ボタンを押し忘れた場合に、実際の開始時刻を後から修正できる経路を持つ。
- 修正機能は通常画面で目立たせない。

### 7. 交代入力
- チームを選ぶ。
- IN / OUT はどちらから先でも選べる。
- OUT候補：現在ピッチにいる選手。
- IN候補：現在ベンチにいる選手。
- 複数人同時交代は「＋もう1組」等で追加。
- 1つの組だけ修正・削除できる。
- 同じ選手を同一イベント内で重複使用できない。
- 確定前は何度でも変更でき、試合状態へ影響しない。
- HOME / AWAYを途中で切り替えても、それぞれの未確定ドラフトを保持する。
- 交代が実施されなかった場合はドラフトを破棄し、履歴・状態・カウントへ影響させない。

### 8. 交代確定
- 「交代を確定」は、その交代が実際に行われたことを記録する操作。
- 選手が第4審判の場所へ来ただけでは確定しない。
- 確定時に時間を自動記録する。
- ルーティン交代に二重確認ダイアログは不要。
- 確定後は短い完了表示のあと、すぐ次の操作へ戻れる。

### 9. 自動判定
- 通常交代 / 再出場をアプリが自動判定。
- 利用者に「通常」「リエントリー」を選ばせない。
- 入力順序によって合法 / 非合法が変わらないよう、複数交代グループ全体を一括評価する。
- HTで同一グループ内に「最後の未出場FPの初出場」と「再出場」が含まれる場合も、確認済み運用に従いグループ全体で判定する。

### 10. 後半の交代機会
- 各チーム独立して3回。
- 後半開始後にのみ消費する。
- HT交代は消費しない。
- 同じチームの同じタイミングの複数交代は1回。
- 0回になった後は通常交代・再出場を行えない。
- 操作を単に消すだけでなく、「後半の交代を3回使っています」等の理由を示す。

### 11. 再出場
- FP側の未出場交代要員がいる間は、出場済みFPの再出場を許可しない。
- GK登録選手はFP側の解禁条件から除外。
- 条件を前半中に満たしても、再出場可能なのはHT以降。
- 再出場できない選手は、必要に応じて見える状態で無効化し、理由を普通の日本語で示す。
- 「リエントリー条件未達」等の専門用語を主要メッセージに使わない。

### 12. 両チーム同時の交代
- 同一停止中にHOME / AWAY双方の交代があり得る。
- 同一のstoppage/eventとしてまとめられる構造にする。
- HOME / AWAYそれぞれが後半なら各自1回ずつ消費する。
- 一方の入力・確定が他方の状態を壊さない。

### 13. 履歴・修正・取消
- 履歴を状態計算の根拠（source of truth）として扱うイベントログ方式を優先する。
- 確定済みイベントは履歴から修正 / 取消可能。
- 修正・取消後は初期状態から時系列順に再適用して全状態を再計算する。
- 再計算対象：pitch / bench、出場済み、再出場可否、再出場使用、後半交代機会等。
- 過去イベント修正によって後続イベントが無効になる場合、勝手に削除・成立扱いにしない。
- 「この修正により、後の交代記録に確認が必要です」と表示し、影響対象を示す。

### 14. 自動保存・再開
- 重要な変更のたびに進行中試合をローカル保存する。
- 再読込・ブラウザ終了後に「進行中の試合があります / 続きから再開」を可能にする。
- Phase 1ではクラウド同期は行わない。

### 15. エラー文言例
- 「まだ10番は入れません」
- 「まだ出場していない選手がいます：17番」
- 「後半の交代は終了です」
- 「15番はベンチにいません」
- 「8番は今ピッチにいません」
- 「同じ選手は選べません」
- 「同じ選手を2つの交代に入れることはできません」
- 「背番号が重複しています」
- 「7人未満のため開始できません」
