# 01_LOCKED_PRINCIPLES

# 【LOCKED】変更禁止の基本原則

## 最上位目的
**リエントリーを理解していなくても、両チームの交代を安全に管理できるアプリにする。**

利用者にルールを覚えさせるのではなく、アプリ側がルールと出場履歴を管理して助ける。

## 対象ユーザー
- 第4審判の経験が少ない人
- 初めてリエントリー方式を扱う人
- 中学生
- 経験のある審判

## 操作原則
基本操作はできるだけ、
**チームを選ぶ → IN / OUT を選ぶ → 交代を確定**
に近づける。

- IN / OUT はどちらから先に選んでもよい。
- 通常交代か再出場かは利用者に選ばせず、アプリが自動判定する。
- 確定前の入力は仮入力。何度変更・削除しても試合状態へ反映しない。
- 「交代を確定」した時点で初めて履歴・出場状態・各カウントへ反映する。
- アプリが分かっていることを、確認のためだけに利用者へ再質問しない。

## UI原則
- 背番号を主役にする。
- 背番号は1〜99。連番を前提にしない。
- 試合中は登録済みの番号だけを大きな選択肢として扱う。
- 色だけで状態を伝えない。文字・アイコン等も併用する。
- できない選手は原則として消さず、必要に応じて選択不可状態で理由を分かりやすく示す。
- 専門用語をできるだけ使わない。
- 試合中に素早く操作できることを優先する。
- スマホで使いやすく、片手でも扱いやすいことを意識するが、片手操作専用にはしない。
- 試合時計は交代操作中も確認できるようにする。
- ルーティンの交代に余計な確認ダイアログを増やさない。
- 前半終了・試合終了など高影響操作には誤操作防止確認を入れる。
- シンプル化のために必要な安全性・正確性を削らない。

## 開発原則
Phase 1では必須機能を完成させる。
便利機能は構想として残し、実戦テスト後に判断する。

**未確定事項を推測で実装しない。**
